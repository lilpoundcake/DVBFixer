# Protpardelle cc94 production integration

New Protpardelle installations use **cc94_epoch3100**, a multichain all-atom
checkpoint. MODELLER remains the default preparation/modeling backend; this
change replaces the model behind the explicit Protpardelle diffusion selection.
The GUI uses the same installed runtime as model, Homology and ZBS.

## Evidence and scope

The [9CQD matched-ODE pilot](../../docs/research/9cqd-cc94-multichain-comparison.md)
passed **5/5** primary seeds in each conditioning arm after generated-only
Reference refinement, versus cc89 ODE controls at 1/5 and 0/5. This is a single
N-terminal tail, not general internal/terminal gap qualification. New profile
metadata labels cc94 separately and does not reuse cc89 cohort acceptance.
Native Mac installation, model/Homology/batch/resume/ZBS and additional
predeclared source cases have since executed. MPS metadata is now
**experimental, case-tested**, with broader qualification explicitly pending;
see the [native follow-up evidence](../../docs/installation-profile-acceptance.md#native-completion-follow-up-after-daaf850-2026-10-30).
The prepared 5J13 cohort accepted only 1/5 seeds, retaining four geometry
rejections. No CUDA-to-MPS, training-disjoint or general reconstruction
qualification claim is made by these native case results.

An additional full seven-gap 9CQD seed-7 production-wrapper run completed sampling
and Reference refinement with zero missing/generated-name errors, zero fixed
displacement, zero detectable D-Cα and zero repository severe clashes. Its final
geometry was **rejected** for one nonplanar amide and one Ramachandran outlier.
This verifies the execution/provenance path, not seven-gap acceptance. The first
pre-generation attempt exposed an unwanted refinement import in the sampling
artifact reader; that dependency was removed and is covered by a subprocess test.

Canonical-protein source selection and per-gap budgets remain fail-closed.
Independent local execution supports N/C-terminal and multiple gaps with at most
512 selected tokens per gap and 64 gaps per candidate. Every gap conditions only
on original observations. Complete merged output passes the existing independent
validation/publication gates. A completed process is not an accepted structure.
The legacy `cc89_*` backend-option keys remain the on-disk context vocabulary;
cc94 declares `cc89_chain_phase=native`, not the cc89 rotary neutral intervention.

The low-level production runner saves native arrays, atom identities and raw
RunnerResult before chemical validation. Actual denoiser position/chain arrays
are checked at every update. The trace requires the cc94 checkpoint digest,
native-relative encoding, ODE identity and 500 position observations. Source
fallback, checkpoint substitution and silently reverting to cc89 are forbidden.

## Obtain the pinned weights

Use the operator-provided files or download the official
[Zenodo archive](https://zenodo.org/records/16817230) under its published terms.
The archive is 4,294,232,741 bytes, published MD5
`59fc043a9d981d6c74baa2d051ea164a`. Extract
`protpardelle-1c/model_params/weights/cc94_epoch3100.pth` and
`protpardelle-1c/model_params/configs/cc94.yaml`; retain the layout:

```text
model_params/
  configs/cc94.yaml
  weights/cc94_epoch3100.pth
```

The checkpoint file is 301,344,516 bytes including optimizer state. Parameters
are about 96 MiB FP32 (25,169,791 parameters). Strict checkpoint loading is
required. Peak PyTorch CUDA allocation on the 189-token case was about 288 MiB;
this is not a measured MPS memory requirement.

## Configure and register

Use separate core, sampling and refinement environments. Keep `CHECKPOINT` as
the absolute path to the new cc94 weights; copying/renaming cc89 weights fails
digest validation. New Protpardelle requests require a new cc94 launcher even if
an old cc89 launcher is installed.

Linux sampling uses [environment-cuda.yml](environment-cuda.yml) with NumPy 2.4.6;
the pinned callback patch is required even though reinjection is disabled:

```bash
git -C "$PROTPARDELLE_ROOT" checkout ee378400f25b801fa481028000f9060183d7fb4c
git -C "$PROTPARDELLE_ROOT" apply --recount \
  "$DVBFIXER_ROOT/deploy/protpardelle-1c/per-step-callback.patch"
```

Apply only to a clean engine checkout. For Reference refinement, use the core
Python 3.13 environment with OpenMM 8.6.1, PDBFixer 1.12.0 and NumPy 2.4.6; a
CUDA refinement runtime is no longer required by cc94 on Linux.

Apple sampling uses [environment-apple-arm64.yml](environment-apple-arm64.yml)
and **only** [apple-portability.patch](apple-portability.patch) in its own clean
engine checkout. Do not combine the two engine patches. Apple refinement retains
the existing native CPU environment. Preserve the venv interpreter path rather
than resolving its symlink to a base Python.

From the platform's sampling environment:

```bash
python "$DVBFIXER_ROOT/scripts/install_diffusion_backend.py" protpardelle \
  "$CHECKPOINT" --engine-root "$PROTPARDELLE_ROOT" \
  --refinement-python "$REFINEMENT_PYTHON"

dvbfixer model source.pdb --fasta target.fasta --backend diffusion \
  --diffusion-model protpardelle -o repaired_bundle
```

Installation registers the platform-specific cc94 launcher. Preflight verifies
host, framework, source/config/checkpoint hashes and actual accelerator/refinement
kernels. On Apple it disables unsupported-operator CPU fallback and retains
untuned MPS allocator/fast-math settings. No weights are downloaded by registration.

Old cc89 configurations remain explicitly registerable with
`protpardelle-cuda-cc89-legacy`, `protpardelle-mps-cc89-legacy` or the historical
`protpardelle-mps-legacy`; they are excluded from automatic selection for new
requests. A frozen request continues to resolve its original profile by name.
